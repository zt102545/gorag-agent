# 多轮问答关系判断与防重复回答方案

## 问题结论

此前多轮问答不是由 AI 判断上下文关系，而是只要当前问题包含“这个、它、那”等词，就把上一问机械拼接成检索 Query。这样会产生两个副作用：

1. 一个完整的新问题可能被误当成追问，知识库同时召回第一问和第二问。
2. 回答模型同时看到历史问答和拼接后的检索 Query，容易再次回答第一问。

这属于对话编排逻辑问题，不是 Redis、BM25、向量索引或前端配置问题。

## 新处理链路

```text
当前问题 + 上一轮完整问答
          |
          v
AI 上下文关系判断
  |                     |
  | 独立新问题          | 真正追问
  v                     v
原样保留当前问题     只补齐缺失对象
  |                     |
  +------> 意图路由 <---+
             |
             v
      BM25 + 向量混合检索
             |
             v
只回答当前问题；历史只用于理解指代
```

关系判断只读取最近一轮完整的“用户问题 + 客服回答”，避免更早的历史主题干扰。本轮回答仍可读取会话历史，但有独立系统约束要求模型：

- 新问题只回答新问题，不复述上一问。
- 追问只补充本次需要的新信息，不重复已回答内容。
- 检索改写仅用于知识召回，不能被当作多个待回答问题。
- 产品事实必须由本次检索知识直接支持，不得从常识推断价格、优惠、期限、规则或功能。

## 判定规则

| 场景 | 判定 | 检索 Query |
|---|---|---|
| 上一问“单分镜改写有什么用”，当前问“批量改写如何收费” | 新问题 | 原样使用“批量改写如何收费” |
| 上一问“单分镜改写有什么用”，当前问“那如何收费” | 追问 | “单分镜改写功能如何收费” |
| 两个问题主题接近，但当前问题主体和诉求完整 | 新问题 | 强制使用当前问题原文 |
| AI 判断失败、JSON 无效或追问置信度低于 0.65 | 安全回退 | 只使用当前问题原文 |

即使模型在“新问题”结果中错误输出了拼接文本，服务端也会覆盖为当前问题原文，形成硬保护。

## 回答路由调整

- 独立新问题高置信命中 QA：仍可直接返回第二问的标准答案。
- 追问高置信命中 QA：不直接返回整段标准答案，交给回答模型基于知识内容生成本轮增量答复。
- 中等置信命中：模型基于检索知识回答，但必须遵守“只回答本轮”的约束。
- 无法判断关系：宁可丢失省略的上下文，也不把上一问错误带入第二问。

## 可观测性

会话 Trace 新增 `query_relation` 步骤，记录：

- `is_follow_up`
- `confidence`
- `reason`
- `standalone_query`

关系模型调用失败时会记录 `query_relation` AI 错误，同时继续用当前问题检索，不中断客服回复。

## 测试覆盖

- 真追问能生成独立检索问题。
- 新问题无法夹带上一问文本。
- 低置信追问安全回退为当前问题。
- 没有完整历史轮次时不额外调用关系模型。
- 最终回答消息包含“只回答当前问题、不得复述上一轮”的系统约束。
- 无状态问答接口能完整聚合 Agent 的流式消息，避免追问进入模型生成路径后返回空答案。

验证命令：

```powershell
go test ./...
```

本方案只修改后端智能体编排，不需要前端改动，也不新增用户配置项。
